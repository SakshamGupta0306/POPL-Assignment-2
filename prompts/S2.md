racket
;; my-length : list -> non-negative integer
;; Number of top-level elements of lst (a sublist counts as 1).
;; Recursive reading: the length of () is 0; the length of (a . rest)
;; is 1 + the length of rest.
;; Tail-recursive: the count is carried in the accumulator acc,
;; so stack use stays constant even for 10,000+ elements.
(define (my-length lst)
  (let loop ((rest lst) (acc 0))
    (if (null? rest)
        acc
        (loop (cdr rest) (+ acc 1)))))

How it works: a named let called loop walks down the list. Each step drops the first element with cdr and adds 1 to acc. At () it returns acc. The recursive call is the last thing the function does, so Racket reuses the stack frame, which is why it's safe on the 10,000-element hidden tests. It only uses define, named let, if, null?, cdr and +, all of which are allowed.

racket
;; my-map : (any -> any) list -> list
;; Applies f to every top-level element of lst and returns the new
;; list of results, in the same order.
;; Recursive reading: mapping f over () gives (); mapping f over
;; (a . rest) gives (f a) consed onto the mapping of f over rest.
;; Only one level deep: f decides what to do with sublists.
(define (my-map f lst)
  (if (null? lst)
      '()
      (cons (f (car lst))
            (my-map f (cdr lst)))))

How it works: it applies f to the first element, recurses on the rest, and joins the two with cons, so the order stays the same.

Why it isn't tail-recursive: a tail-recursive map builds the result backwards and then has to reverse it, which would mean also writing my-reverse. Racket grows its stack as needed, so ordinary recursion over 10,000 elements is fine. Even so, run the stress test below to confirm; it's also a likely viva question.

How it fits insert-if-short: my-map only goes one level deep. When you write insert-if-short, the function you pass to my-map will check each element. A sublist gets processed recursively, and an atom is left as it is. That is how the nesting gets handled.

I've added insert-if-short to id_q4.rkt, which now has all three S2.b functions. Racket isn't available here, so I checked it by hand against all four examples from the PDF and haven't run it.

racket
(define (insert-if-short x lst n)
  (let ((processed
         (my-map (lambda (e)
                   (if (or (pair? e) (null? e))
                       (insert-if-short x e n)
                       e))
                 lst)))
    (if (< (my-length lst) n)
        (cons x processed)
        processed)))

How it works:

my-map goes over each element of lst. A sublist is handled by calling insert-if-short on it again; an atom is left as it is. That covers every level of nesting.
Then it checks the outer list. If the original lst had fewer than n elements, it puts x on the front.
The length comes from lst, not processed. That's how it follows the rule "measured before any insertion".
A list is detected with (or (pair? e) (null? e)) because list? isn't allowed. The null? part makes empty sublists become (x).

;; make-inserter : atom (number -> boolean) -> (list -> list)
;; Returns a one-argument function that inserts x at the front of
;; every list, at every nesting level (the list it is given included),
;; whose ORIGINAL length satisfies len-ok?.
;; Recursive reading of the returned function ins: process every
;; element of lst (sublists by ins itself, atoms unchanged); then, if
;; (len-ok? (my-length lst)) holds, cons x onto the front of the result.
;; An element is a list if it is a pair or (), since the allowed
;; built-ins have no list?.
;; letrec lets ins refer to itself for the nested lists.
(define (make-inserter x len-ok?)
  (letrec ((ins
            (lambda (lst)
              (let ((processed
                     (my-map (lambda (e)
                               (if (or (pair? e) (null? e))
                                   (ins e)
                                   e))
                             lst)))
                (if (len-ok? (my-length lst))
                    (cons x processed)
                    processed)))))
    ins))
